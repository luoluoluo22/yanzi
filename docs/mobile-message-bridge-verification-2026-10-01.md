# 手机与电脑消息通信专项验证（2026-10-01）

## 修改结果

- Android 登录后从前台启动跨端消息前台服务；每 5 秒串行读取云端收件箱，每 30 秒注册/更新设备心跳。支持电脑发来的 `notify` 和 `text`。
- 系统通知展示后保存本地收据，再 ACK。网络失败退避重试；通知被禁用时保留 pending，重新授权后补收；未知消息类型明确返回失败。
- 通知与相机使用不同的权限请求码，避免 Android 13+ 通知授权后误启动相机。
- Windows 启动 5 秒轮询兜底，并串行处理 SSE/轮询消息；进程内缓存执行结果，避免并发重复执行。
- LAN 通知校验 Bearer Token，按 UTF-8 字节读取请求体；通知不可用时返回失败，允许电脑转用云端。生产手机端口 42981，Dev 42982。
- 实际真机进程重启暴露的服务启动异常已修复：服务从 Activity `onResume` 启动，后台启动限制不会阻断主界面。

## 验证方法与范围

使用实际 Android 11 手机上的隔离包 `cc.luoluoluo.yanzi.mobile.dev`，配合实际 Windows WPF 消息桥及临时本地 Worker/D1。通过 ADB reverse/forward 连接测试服务，使用临时账号，不访问线上账号消息数据。

回归入口：`scripts/test-real-phone-message-bridge.ps1`。测试前备份 Dev 偏好，结束后恢复账号配置、通知设置并撤销网络映射；生产包 APK 路径和版本前后核对一致。

已通过的完整回归包含：

1. Windows 消息桥启动与并发重复执行防护。
2. 手机、电脑注册上线，以及后台心跳持续更新。
3. 前台、后台和熄屏通知展示与 ACK；系统通知记录核对。
4. 禁止通知时不误 ACK，重新允许通知后补收。
5. 不支持的消息类型标记失败。
6. 断网期间保留消息、恢复网络后补收。
7. 真机发送文本至 Windows；真机发起 Windows 命令，手机读取实际执行结果。
8. LAN 未授权请求拒绝，携带配对 Token 的中文通知成功。
9. 手机强制停止后重开补收。
10. 停止心跳后等待完整 120 秒窗口，验证双端离线；手机重开重新上线。
11. 生产包保持原状，Dev 原有配置恢复。

## PC 日志与环境修复

用户已确认 PC 主界面恢复。另发现本地 API 的 `HttpListenerException (32)`：Windows 的 TCP 保留范围 53899–53998 包含配置端口 53919；独立绑定测试同样失败。

保留原配置备份后，将本机 API 端口改为 42980，重启燕子，`http://127.0.0.1:42980/health` 返回 `ok=true`。未修改用户的 LAN 启用设置。本地 API 调用方需要使用新端口。

## 实际限制

- 本次真机为 Android 11。Android 13+ 的运行时通知授权和 Android 14+ 的前台服务分支完成编译，尚未在对应系统真机验证。
- 云端接收采用前台服务轮询，尚未接入 FCM；用户强制停止 App 后，需要重新打开才能恢复接收，厂商电池策略仍可能限制后台运行。
- Windows 去重缓存限于当前进程，不能保证电脑重启后的命令恰好执行一次。
- 完整故障场景回归使用临时 Worker；公网另验证了双向文本/通知，公网命令执行结果回读未单独重复验证。本次没有发布生产 APK 或部署 Worker。

## 聊天窗口回退修复

用户从聊天窗口实际发送后发现失败：这个入口原先仅调用 LAN，未使用已接入的通知云回退。此前公网消息测试覆盖了 API 链路，遗漏了聊天窗口。

补齐文字发送的云回退、真实接收设备 ID、发送状态与失败保留输入；手机云接收器把 `YanziChat` 文本写入聊天记录并更新界面。照片/文件云传输尚未实现，提示明确要求直连。

`test-real-phone-message-bridge.ps1` 新增实际 WPF 窗口发送流程验证：没有 IP，以及 IP 已失效时，均确认文字进入手机聊天记录。`test-real-phone-public-chat.ps1` 使用已有账号补充公网窗口验证，两种情况同样检查手机实际记录；临时桌面验证目录与生产数据隔离，结束后删除临时凭据副本。
