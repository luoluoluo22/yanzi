# 交互响应与稳定性改进（2026-09-22）

本轮依据 WPF XAML 和事件代码检查搜索、结果选择、视图切换、窗口收起/恢复。当前原生桌面控制不可用，未做截图或实机视觉审查，也未测量实际首帧/P95 延迟。

## 已实现的用户体验改进

| 场景 | 之前的风险 | 本次处理 |
|---|---|---|
| 连续输入与切换搜索范围 | SearchSession.Dispose 先设置 disposed，再调用会跳过取消的 Cancel；旧工作可能继续，读取已释放 source.Token 还可能抛异常 | 正确取消并释放，缓存可安全读取的 token；输入变化立即使旧会话失效 |
| 文件/扩展搜索等待 | 防抖期间仍保留旧结果和选择，快速回车可能运行旧项 | 新查询待处理时阻止结果点击与执行；上下键/回车先刷新防抖；替换式异步搜索清除旧项并显示搜索进度 |
| 异步取消或失败 | 多个未等待 Task 缺少统一异常边界，加载状态容易遗留 | 文件搜索、扩展搜索、全范围补充和图标加载统一观察异常；仅当前会话有权结束自己的加载状态 |
| 无结果或搜索失败 | 结果区空白，搜索错误写入同步状态，位置不匹配 | 结果区显示无结果、服务失败、未启用、输入文件名等反馈 |
| Everything 尚未初始化 | 普通输入触发模态确认框 | 改成非模态提示与显式“打开文件搜索服务”按钮 |
| 列表内容未变 | 每次 ReplaceAll 都发 Reset，触发容器/选择重建；容量随结果数收缩 | 同序列直接返回，保留容量；先快照再替换，支持延迟枚举和自引用；纠正 Replace 事件新旧值顺序 |
| 长结果列表 | 列表已有虚拟面板但没有显式启用 Recycling | 启用容器复用与内容滚动；网格仍使用原有 WrapPanel |
| 列表/网格切换 | 先显示全屏遮罩并等待 16ms，多次点击可以并行保存 | 立即切换，保持当前选择可见；串行完成偏好保存并报告保存失败 |
| 收起再打开 | 取消搜索后不恢复，甚至有子窗口阻止隐藏时也会取消 | 真正隐藏才取消；停止防抖定时器；重新显示时恢复未完成搜索；退出时清理管道 |

## 后续建议，按收益排序

1. **实机交互回归**：快速输入后 Enter、中文输入法候选确认、搜索中 Esc 后重开、断开 Everything、扩展搜索超时、多屏 DPI、键盘/鼠标导航。检查新提示在浅色/深色和较大字体下的布局。
2. **首屏延迟观测**：记录呼出到首帧、输入到本地结果、后台补充完成的 P50/P95；先测量再调整 40/120/150ms 防抖，不以减少等待常数代替修复阻塞。
3. **网格虚拟化**：WrapPanel 仍会生成全部卡片。扩展很多时，采用经过键盘导航、拖拽、可访问性验证的虚拟网格，或先限制首批展示数量。
4. **稳定补充结果**：全范围文件补充仍会重新排序。已保留当前选择，但排序带来的位置移动需要实机确认，尤其鼠标悬停/准备点击期间；可考虑用户开始导航后固定已有行的位置。
5. **搜索统计与首帧分离**：UpdateSearchScopeCounts 会扫描各范围命令，规模较大时应延后非当前范围计数，或用版本化缓存减少重复匹配。
6. **浮层与同步反馈**：继续清理钩子同步等待 UI、面板呼出路径中的强制 UpdateLayout；同步使用不遮挡主操作的状态和失败后可重试入口。此轮没有改这些流程，也不宣称已消除全部卡顿。
