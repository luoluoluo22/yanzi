# K70 公开内容原生无障碍快照研究 · 0.2.77

日期：2026-10-17。延续 B站、小红书、抖音的公开推荐页面研究。用户明确“不碰微信、封装留到后面”，因此当前只添加最小可验收的读取接口，不做后台抓取器、网络解密或通用第三方 App 数据采集。

## 问题和归因

- 上一轮 B站、抖音的动态图像页面，传统 Android `uiautomator dump` 返回 `ERROR: could not get idle state.`，导致 10 页截图成功但 XML 0/10。此前不能把它视为“屏幕没有文字”。
- 旧 `mobile.screen.tree` 需要经云端设备消息回执。第一次试验超时后检查发现 K70 **设备离线**，`lastSeenAt` 刚好停在 APK 更新时段。通过正常打开“燕子”客户端，设备恢复在线；说明那次超时至少有**设备消息服务未恢复**的因素，并不能归咎于 B站 UI。
- 重复采集的后续一次云端请求连续返回 `pending` 超过 26 次轮询，即便设备在线。说明**消息投递 / ACK 延迟仍存在间歇性问题**。目前不能宣称全部连续云端采样稳定，具体需要后续查看移动端能力队列领取和 ACK 行为。

## 新增的安全读取能力

已安装 Android 0.2.77 到测试 K70，APK 与之前同一正式签名。

- `mobile.screen.inspect`：只允许 `tv.danmaku.bili`、`com.xingin.xhs`、`com.ss.android.ugc.aweme` 三个包名；输入 `{"packageName":"tv.danmaku.bili"}`。
- 必须保持燕子远程屏幕控制开关开启、Android 无障碍连接有效、手机已经解锁；还检查**请求目标应用确实是当前活动窗口**。禁止后台跨 App 读取。
- 手机端在主线程通过 `AccessibilityService.getRootInActiveWindow()`（MIUI 允许时回退当前焦点应用窗口）直接读取，绕过 UIAutomator 的界面空闲等待；只返回含 text/contentDescription 的节点及边界、视图 ID。密码节点不读取内容。
- 限制最多遍历 260 节点、最多返回 85 个文字节点、深度 18、约 1750ms 遍历预算；返回 `truncated` 标识。响应可能被截断，不能以此证明全部卡片已采集。
- 继续使用燕子已有的登录账号和 Capability 授权，不开放未验证的任意网络端口。云端执行完毕后清除手机端暂存回执。
- 私有数据只落在 Windows `%LOCALAPPDATA%\OpenQuickHost\NetworkCaptures\K70\native-public-feed\`，不会提交 Git。

## 真机获取结果

| 观察值 | B站第一页 | B站第二页 | 小红书第一页 | 抖音第一页 |
| --- | ---: | ---: | ---: | ---: |
| 遍历节点 | 97 | 98 | 72 | 83 |
| 返回文字节点 | 74 | 85 | 42 | 50 |
| Android 端执行耗时 | 232ms | 148ms | 129ms | 144ms |
| 结果被节点上限截断 | 否 | **是** | 否 | 否 |
| 提取到结构化卡片 | 5 | 7 | 6 | 1 |
| 已提取卡片的作者有值 | 5/5 | 7/7 | 6/6 | 1/1 |

B 站上下两屏共 12 次卡片出现，按标题和作者去重后 **9 条不同卡片**，第二屏 4 条新增、3 条重复，与上次两页实验的数量一致。前屏视频卡片含播放量和时长，第二屏视频卡片的这两项均可提取。小红书本屏 6 张笔记卡片都有作者/点赞数；抖音本屏作者、文案、点赞/收藏/分享均可提取。

这些数据是**当前可见屏幕**的字段，不是私有缓存、好友消息或完整服务端内容。B 站第二屏截断意味着可能遗漏末尾节点，不能把本次成功率视为长期完整召回率。

## 研究和重复调用

桌面使用 `scripts/yanzi-phone-inspect.ps1`，默认三个固定包名之一；按现有燕子云端通道提交命令，输出仅提供节点数及耗时，原文只保存本地 JSON。

```powershell
# 手机上应保持目标应用的公开首页处于前台
& .\scripts\yanzi-phone-inspect.ps1 -PackageName 'tv.danmaku.bili'

# 将保存的多个快照转换为标题/作者/点赞等结构化卡片并去重
& 'C:\Program Files\Python312\python.exe' .\scripts\yanzi-native-public-feed-parse.py `
  '<本地第一屏快照.json>' '<本地第二屏快照.json>'
```

`scripts/yanzi-native-public-feed-parse.py` 复用旧的 B站/小红书/抖音可见内容解析器，不再调用 UIAutomator。遇到目标窗口错配、远程超时或锁屏，应该明确标记失败，**不能算为 0 条内容**。本地 JSON 快照在下一次运行助手脚本时按 7 天过期清理，不是后台强制自动清理。

## 测试

- Android Release 编译成功，已确认 K70 `versionCode=77, versionName=0.2.77`，无障碍服务授权仍保留。
- Java 限定包名 smoke：允许 3 个公开 App、拒绝微信、系统设置、任意金融包名以及其他未允许包名（共 6 项拒绝）。
- Python 快照转换单测：包名限制、字段结构转换、缺失数值处理。
- B 站两次、小红书一次、抖音一次的真实云端快照：手机原生执行 129–232ms，完成结构化内容读取。
- 抖音的另一次请求停留在云端 `pending`，这属于**未投递或未被手机及时领取**，而非已执行的控件读取错误，需要下一轮专门修复队列调度和回执延迟。
