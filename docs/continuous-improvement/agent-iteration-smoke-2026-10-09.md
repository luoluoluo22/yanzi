# 燕子父子 Agent 实战迭代首轮验收（2026-10-09）

## 验收目标

不是验证 ChatGPT 是否知道如何写代码，而是验证子 Agent 能否在本机完成**修改源文件 → 运行固定测试 → 回传结果 → 不通过则重新修改**。任何仅有自然语言完成声明、代码块或 Job accepted，都不算成功。

实验隔离目录：`.tmp/yanzi-iteration-lab/`。不允许触及生产版本、运行中的燕子扩展、其他用户数据。每道题的测试文件由父测试器创建和维护，子 Agent 只可以编辑相应源码文件。

## 派发实测过程

1. 尝试创建实验父 Agent 两次。分别出现“等待发送按钮超时”和“ChatGPT 标签页加载超时”，均标记待复核，不会盲目重新提交。
2. 子任务 T1 使用 `parentTaskId=lab:iter-20261009` 创建新聊天，失败“ChatGPT 标签页加载超时”。复用此前已经成功的测试子 Agent 对话再次派发，任务最终超时，未写文件。
3. 用已保存的受管理测试标签页执行最简单的 PING（只要求回复固定字符串），仍然超时。
4. 加入只读 `chatgpt_diagnostics`，本机在两个受管理的旧测试标签页看到 `status=complete`、`discarded=false`，但脚本注入 10 秒无响应。证明 Bridge WebSocket 在线不代表后台网页渲染可用。
5. T2 作为独立新子 Agent 再试，实际进入页面交互阶段，但在发送前因为“输入框已有其他草稿”被安全拒绝。**没有覆盖草稿**，也没有实际写入源文件。
6. 父事件邮箱 `GET /api/parent-tasks/lab%3Aiter-20261009/events` 累积 4 条事件（T1/T2 各一条 dispatched、finished），错误状态/正文可查询。父对话网页未能可靠初始化，因此没有声称它收到了新回复。

## 已实际完成的工具链改进

- Edge 扩展 v0.5.54：新增 **read-only** `chatgpt_diagnostics`（加载状态、是否有发送按钮、是否需要登录/验证码、页面渲染可用性；不读取消息正文），并限制 `chrome.scripting.executeScript` 注入等待时间。页面无响应时报告明确错误，且不自动重复提交。
- 对应 Bridge API 支持 `chatgpt_diagnostics`。
- 全套 Bridge 回归 **65/65 通过**，但这是协议和模拟环境测试，并不等于真实网页端到端测试通过。
- 仅清理了实验中创建且已确认不是运行中任务的三个空白测试标签页，没有触碰用户当前聊天或生产程序。

## 下一步工程门禁

将开始新一轮真实开发前的前置条件定义为：
1. **浏览器自动化可用性门禁**：先对将被派发的独立标签页运行 DOM/输入框只读探测，不能对冻结页面发起开发任务。
2. **账号/草稿隔离**：将实验子 Agent 放入独立 Edge 测试 Profile（需用户首次完成一次登录），避免与主 Profile 的聊天草稿及扩展状态冲突。
3. **工具权限证明**：子 Agent 必须实际修改 allowlist 中的文件并使固定测试变绿；没有权限则归类 `TOOL_UNAVAILABLE`。在此之前绝不能将“回复了补丁文本”称为代码开发成功。
4. **失败反馈状态机**： `queued → browser_ready → submitted → code_changed → tested → passed/failed`；途中任何未通过状态都保留 Job、日志、工作区快照，不能自行发布。
5. 再次试运行 T1/T2/T3 后，才考虑接入燕子真实 OCR、截图、设置页等模块。部署正式环境仍需回归门禁。

本报告如实说明首轮失败。下一轮应优先解决后台浏览器可靠性，而非通过人工偷偷修改测试文件制造通过率。
