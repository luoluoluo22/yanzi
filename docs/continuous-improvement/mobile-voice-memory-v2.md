# 燕记声音记忆：AAC 低存储方案（开发验证中）
2026-10-11 / 基于 b76e275 MVP，分支 feat/mobile-voice-memory-v1

## 技术方案
- 采用原生 AudioRecord 捕获 16 kHz、单声道、16-bit PCM，编码器为 Android MediaCodec AAC-LC 32 kbps。
- 存储为连续 ADTS AAC 帧组成的 `.aac.partial`，封存后改为 `.aac`。不依赖 M4A/MP4 尾部索引，意外退出时可按 ADTS 帧长度找到最后一个完整帧并截断残余字节。
- 同时保留 WAV 无损回退方案；开始录制时选择 AAC 或 WAV，在录音期间锁定配置。
- 默认 15 分钟分段；仅 QA/debug 模式提供 8 秒分段验收，正式录音不会启用 QA 短分段。
- 列表兼容既有 WAV 与 AAC；显示文件名、大小与基于 AAC 帧数估算的时长，缓存结果避免反复读取。列表顶部显示全部录音段数、累计时长及总大小。
- 录音后支持 Android 系统文件选择器主动导出单个片段，文件写入用户选择的位置，不后台上传。当前导出页面交互仍需手机解锁后实机验证。
- Android 云备份与设备迁移排除原始音频；卸载测试包前应主动导出。未实现本地用户级加密、定时日程、12 小时脱电续航、AI 语音分析。

## 合成音源验收（真机 MediaCodec，不调用麦克风）
`am instrument -w -e suite voice-memory-codec cc.luoluoluo.yanzi.mobile.voiceqa.test/cc.luoluoluo.yanzi.mobile.LanRecoveryTest`
- 约 3 秒 440Hz 合成测试音 → 12098 字节 AAC，系统 MediaPlayer 可以读取。
- 封存 AAC 的 ADTS 帧数测得 2944 ms；与三秒输入接近（约 56ms 编码尾帧差异，后续须精测）。
- 模拟未正常 EOS 直接终止编码器，且故意附加损坏的 ADTS 头部字节，恢复后仍保住至少 1600 ms 的完整音频帧，损坏尾字节被丢弃。
- 这只能证明压缩编码与恢复；不能代替真实麦克风录音验收。当前真机图案锁屏未解锁。
- 存储预计（32 kbps，忽略 ADTS 开销和元数据）连续 12h ~173 MB；WAV 16 kHz 16-bit 12h ~1.38 GB。实测请从实际文件汇总统计。
