# 燕子 Git 工作树生命周期规范

生效日期：2026-10-19。适用于燕子的 AI 开发任务与手动 Git worktree。

## 唯一代码基准

- **正式集成基准统一使用 origin/main**。旧分支与主线冲突时，保留主线已验收的新架构；不可整树覆盖新实现。
- Git worktree 是临时隔离的开发目录，不是永久功能存档。
- **常态上限 5 个工作树**：正式 main 集成目录、原始活动开发目录、最多三个并行任务目录。
- 创建新工作树前执行：powershell -NoProfile -File scripts/check-worktree-cap.ps1 -MaximumWorktrees 5 -Strict
- 超额必须先核对并移除过时工作树。分支历史与工作树目录分离管理。

## 创建 → 开发 → 验收 → 合并 → 关闭

1. 新任务以最新 origin/main 为基线，不从旧双进程 Runtime、旧发行版或无维护的实验分支继续派生。
2. 每个任务明确负责人、完成条件和独立工作树，验证兼容性后才合并 main。
3. 任务合并验收后**同一轮清除工作树**，而非永久留存。
4. 干净且无人维护的任务工作树超过七天，应优先清理；超过五个上限时及时清理更旧目录。
5. 无法证明比 main 更合适的旧架构，原则上归档、清除工作树；有价值的部分从 Git 历史按需抽取。
6. 保留正式运行程序、真实用户小程序安装目录、用户数据，以及仍然实际活跃的开发工作树。

## 清理安全边界

- 清理前先核对 git worktree list --porcelain、git status --porcelain -uall 和是否有使用该目录的运行任务。
- 干净工作树使用 git worktree remove 操作；正常不会丢失该分支提交历史。
- 有未提交修改的工作树：先保存 git diff HEAD --binary，再把未跟踪和已修改的文件打包到工作树外；记录 HEAD、分支和 SHA-256，校验备份后方可强制移除。
- detached HEAD 的独有提交应建立存档引用；本地旧 main 有分叉时必须保留旧 main 引用，再对齐 origin/main。
- 删除失败时不得粗暴递归删除根目录。需确认工作树登记已退出、备份可用、没有占用进程，才能清理孤立残留。
- 每轮清理后重新验证工作树数量、main SHA、受保护工作目录状态和备份索引。
