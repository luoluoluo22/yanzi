# 统一任务与进度浮窗

手机 chat.send、内置微信文件助手文字发送及微信标注业务能力共用宿主任务记录和浮窗。小程序按需加载仍静默，手动入口才显示标注主窗口。

## 请求和回执

- 发送请求可携带 requestId（8～200 字符）。MCP 在支持该字段的新发送工具中自动补齐遗漏的 ID；传输失败保留原 ID，不自动重发。
- taskId 按账号和 requestId 派生。相同请求返回原结果；同 ID 不同业务参数拒绝。附件签名包含内容哈希。
- 记录按账号存储在用户数据目录 operation-tasks。提交边界先落盘，异常恢复为 unknown，不重新执行不可确认的发送。
- task.status：只读查询 taskId 或 requestId，手机和附件按原回执核对；手机已完成任务也可继续刷新其他设备回执。
- task.cancel：提交前请求中断。已经提交时继续查询原回执，不能撤回。
- task.health：活动任务与能力提供者健康信息。
- task.begin/update/check/submit/finish 为内部协作能力，MCP 不向用户工具目录暴露；上述三个公开查询/取消/健康工具自动发现。

## 方案一：来电胶囊

原生深色浮窗 460 × 164 DIP，左侧业务图标，中部身份/动作/对象，右侧图标和状态胶囊，下方为阶段动画和中断提示。

| 状态 | 颜色 | 提示 |
| --- | --- | --- |
| 执行中 | 蓝色 | Esc ×2 中断 |
| 已提交 / 等待回执 / 结果未知 | 琥珀色 | 已提交，无法撤回 |
| 完成 | 绿色 | 结果短暂保留 |
| 失败 | 红色 | 失败阶段短暂保留 |
| 中断 | 灰色 | 保留草稿 |

进行中是循环动画，没有估算百分比；终态保留约两秒后关闭。多任务显示当前任务和任务数量。窗口不激活、不抢焦点、不显示任务栏按钮，保持点击穿透。

双击 Esc 为 700ms 内两次独立按键，按住键产生的重复事件不算第二次。只作用于显示中的可取消任务。提交后 Esc 恢复正常传递，不声称可以撤回。提交前同时检查钩子和 Windows 输入桌面可用性；安全桌面不可访问时阻止提交。

## 验证

Release 构建通过并自动激活，五状态原生渲染检查、键盘回调隔离验证、任务记录 17 项回归通过。安装后浮窗显示和任务结束自动关闭已观察。当前 Windows 输入桌面拒绝访问，实际全局 Esc 注入验收尚待解锁后完成；不把这个环境下完成的手机测试消息误记为取消成功。视觉证据见仓库根目录 design-qa.md。
