# Android 0.2.45：局域网短暂失败与恢复

## 日志依据

一加日志在 22:36:21 记录连接 192.168.1.100:42980 失败，随后广播发现超时。电脑日志在 22:37:17 记录重新启动 Local Agent API / UDP 发现服务，手机在 22:37:28 恢复加密直连。这段时间与电脑端重启吻合；没有红米日志，不能把全部现场波动归为同一原因。

## 修复

- 新增独立 `LanConnectionHealth`，使用单调时间：正常探测间隔 8 秒；失败后按 5、15、30 秒恢复探测，最多 30 秒间隔。一次短暂失败显示“局域网重连中”，连续两次探测失败或成功记录超过 30 秒才转为不可用，由云端在线状态决定显示云端或离线。记住地址不等于确认连通。
- 传输失败保留已知地址，后续优先直接验证；广播发现的冷却/暂停不阻止已知地址恢复。只有账号撤销连接等明确失效操作删除地址。业务拒绝不作为传输故障更新连接健康。
- 同账号连接信息刷新不再每次重置发现退避并强制广播；健康时复用已验证结果，广播有独立 30 秒冷却。Wi-Fi 网络/地址、账号会话及目标设备变化后丢弃旧健康状态；连接检测不重叠，旧会话结果不能更新界面。
- 电脑页的发现和健康探测只接受电脑设备，拒绝同账号手机以及平台不明的账号连接。保留历史手工电脑配对兼容性。广播接收恢复数据包长度，跳过无效 JSON，并约束发现期限。
- 顶部状态图标和连接文字都明确显示“重连中”，不会把暂存地址显示为已建立局域网连接。
- Dev 传输验收入口跳过正常前台生命周期中的账号刷新，避免临时测试配对被后台替换；正式版不开放该入口。本次没有增加操作自动重放。

## 验证

- 17 项纯 Java 状态/节奏/过期/重置/设备平台判断通过，纳入通信基础脚本；13 项局域网路由边界及既有安全重试、有界响应规则通过。
- 新 Android 原生模拟器故障夹具通过两项场景：真实关闭 TCP 服务，验证短暂失败、持续不可用、地址保留、广播暂停期间直接恢复；HTTP 403 和账号变化不能保持局域网就绪。夹具只允许模拟器和 `.dev` 包，结束清空测试数据并启动 clean smoke。
- Dev / Release 构建通过，Release lintVital 通过。
- 最终 Release 从 0.2.44 覆盖升级、重复安装、回退及再次升级通过；会话、设备身份、偏好、1 MiB 本地文件、75 条历史消息及迁移标记保留，最后清空模拟器合成数据。
- 一加 Dev 0.2.45 安装通过，正式包路径保持不变；完整照片/3 MiB 分块文件、远程读写/列表、不存在文件拒绝、慢终端及重复请求去重通过；电脑到手机照片/文件 SHA-256 和丢失分块确认恢复通过。已恢复原 Dev 配对/账号，未熄屏、未替换正式包。
- 真机测试曾出现临时手工配对被后台覆盖，已修正 Dev 夹具生命周期；中间一轮还出现手工配对 HTTP 401，计数文件确认终端没有执行两次，最后完整重跑和双向传输通过。未把这次有限测试表述为所有 Wi-Fi/VPN 环境已验收。
