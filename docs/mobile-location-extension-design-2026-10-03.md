# 手机小程序「位置」与跨端环境状态设计

状态：2026-10-03 的设计基线；省电首版已实现，实际范围、测试与部署状态见 [实现与验收记录](mobile-location-implementation-2026-10-03.md)。下面的“现有能力”描述实现之前的状态。

## 现有能力

- `DeviceHeartbeatService` 登录后以 remoteMessaging 前台服务运行，显示“燕子实时连接”通知。内部每秒检查调度，正常情况下约 30 秒上报一次心跳、60 秒进行增量同步；有 WebSocket、轮询回退和失败退避。这些是服务存活时的目标频率，不是系统执行保证。
- `MobileDeviceCapabilities.snapshot()` 已读取电量、充电、Wi-Fi/移动网络类型、IPv4 等，电脑可通过既有设备状态/能力接口读取。
- Android Manifest 未声明粗略、精确、后台定位权限或 location 前台服务类型；没有 LocationManager 定位、WorkManager 定位任务或地理围栏实现。
- `mobile-js` 支持被触发后的无界面执行，但运行器生命周期和 JavaScript 定时器不能保证进程被杀、休眠或重启后继续执行。桌面 `app.runInBackground` 约定不等于 Android 定时调度。
- 现有心跳代表设备可通信，不能代表用户正在操作该设备。
- 补充：旧 `context.mobile.getLocation()` 仅提供基于 IP 的粗略地理位置，并非系统 GPS/网络定位，也没有持久后台采集能力；新原生模块独立实现系统定位。

## 用户入口

手机小程序名称「位置」，统一 extensionId 拟定 `yanzi-location`。燕子应用中心/小程序入口打开设置页：

| 设置 | 默认设计 |
| --- | --- |
| 环境上报 | 关闭；用户启用后开始申请所需系统权限 |
| 上报给谁 | 当前燕子账号的已授权电脑；界面显示设备列表 |
| 后台模式 | 省电模式，目标 15 分钟，系统可能延迟 |
| 家的位置 | 点击“将当前位置设为家”，保存手机本地；可编辑和删除 |
| 家的范围 | 初始 200 米，可调，结合实际定位精度判断 |
| 家的 Wi-Fi | 可选绑定当前网络；未授权读取名称时仍可显示是否连接 Wi-Fi |
| 上报内容 | 在家/外出/未知、网络类型、时间及可靠性 |
| 精确坐标共享 | 默认关闭，独立开关和说明 |
| 操作 | 立即检测、立即上报、暂停、停止并清除云端最新状态 |

状态页同时显示“最近采集时间”“最近成功上报时间”“权限/定位开关”“待同步/失败原因”“电脑看到的状态”。不能只显示计划中的下次时间，让用户误以为一定会执行。

## 调度与功耗

1. 首次启用：在可见页面完成权限说明、定位和初次上报；后台权限另行引导，不一次混合申请全部权限。
2. 省电模式：Android 原生持久调度，目标每 15 分钟尝试一次短时定位；配合网络变化和前台恢复做刷新。联网约束用于上传，不阻止离线采集。位置授权不足时显示“仅前台可检测”。
3. 可选及时模式：用户从可见页面明确启动 location 类型前台服务，常驻通知含暂停/停止，目标 5 分钟尝试一次，承认额外耗电及系统限制。不能借现有 remoteMessaging 类型直接执行持续定位。
4. 每次定位限时，例如 20 秒；优先合格的近期缓存，缓存年龄、精度均必须校验。失败时保留“最后已知位置”和原采集时间，当前状态标记未知/过期，不能伪装新定位。
5. 上传合并短时间多次事件，设置防重入和退避；断网只缓存最新状态，不堆积轨迹。恢复网络上传最新有效快照，不补发所有旧坐标。
6. 普通进程死亡/重启恢复由持久调度与用户设置处理；系统强制停止后不得承诺自动恢复。退出账号、关闭功能、移除小程序时取消任务、释放定位和清除对应待发数据。

Android 的 WorkManager 周期任务最短 15 分钟，执行不精确；后台定位更新可能仅每小时数次。通知前台服务也不是永不被系统终止的保证。[周期任务](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)，[后台定位限制](https://developer.android.com/develop/sensors-and-location/location/background)，[location 服务类型与权限](https://developer.android.com/develop/background-work/services/fgs/service-types#location)。

## 在家/外出的判断

- 状态使用 `home / away / unknown`，不强迫二选一。
- 设家半径为 R、估算距离为 d、定位误差半径为 a：`d + a <= R` 才作为明确在家证据；`d - a >= R + 100m` 才作为明确外出证据。边缘区、精度不足、样本过期进入未知或保留带时间的最后已知状态。
- 初始采用两次有效样本或持续时间确认边界变化，避免室内定位漂移导致来回切换。即时模式和省电模式的确认延迟不同，要在界面说明。
- 已绑定 Wi-Fi 为辅助证据，SSID 不唯一，不能仅凭同名网络断言在家；明显冲突时显示“信号不一致”。不连接 Wi-Fi不能推导为外出。
- `wifiConnected`、`internetValidated`、`ssidAvailable` 独立表示：连接 Wi-Fi 不一定能访问互联网，名称不可读不等于没有 Wi-Fi。VPN/同时存在蜂窝与 Wi-Fi 时分别报告底层连接和默认路由。
- Wi-Fi 名称/BSSID 受系统版本、定位权限与定位开关影响；不可读时退化为网络类型。既然用途包含推断位置，不把 Wi-Fi 能力声明为 neverForLocation。[WifiInfo 的敏感字段限制](https://developer.android.com/reference/android/net/wifi/WifiInfo)，[Wi-Fi 权限](https://developer.android.com/develop/connectivity/wifi/wifi-permissions)。

## 判断正在使用哪个设备

位置和使用状态分别提供，之后由电脑端小程序合并：

| 信号 | 能说明什么 |
| --- | --- |
| 电脑最近键鼠输入、锁屏/休眠状态 | 电脑近期可能正在使用；电脑在线本身不足以判断 |
| 手机屏幕亮/解锁状态 | 手机可交互，不证明发生实际操作 |
| 手机燕子前台状态、燕子内最后交互时间 | 用户近期确实操作过燕子；不能覆盖其他手机 APP 的操作 |
| 家/外出、Wi-Fi/同一 LAN | 环境与通信路由证据，不作为直接使用行为证据 |

结果设计为 `desktopLikely / phoneLikely / both / unknown`，附证据时间与理由。第一版不申请全局应用使用记录或无障碍权限；有新需求再评估手机其他 APP 的使用信号。未经直接交互证据，不把“解锁手机”标成确定在用手机。

## 工程边界

建议链路：小程序设置/规则 → Android 原生采集和调度 → 手机本地最新状态/待发记录 → 已认证的同账号通信 → 电脑端环境判断。

- 小程序保存家的范围、Wi-Fi 绑定、启停、状态展示和规则，代码放用户 Extensions 目录，业务数据放 ExtensionStorage，不在宿主代码中加入某个小程序的业务分支。
- 原生执行可采用已有 Android companion 形式，让伴随小程序独立声明定位权限和服务；燕子中保留统一入口和设备通信。若产品要求纯内部 mobile-js 入口，则需先建设可复用的定位权限桥接、设备环境读取和持久后台任务平台能力，明确这是平台建设，不在 MainActivity 中硬编码「位置」轮询。
- 后台采集不依赖保持 WebView 常驻，不向小程序脚本暴露账号 Token；复用已认证 LAN/云路由，按 extensionId、账号、设备限定写入身份。
- 定位适配先覆盖 Android 原生 LocationManager；可选 Google 融合定位/围栏，但不把 Google Play Services 作为所有国内手机的前提。围栏作为第二阶段能力，仍需后台权限和实际设备验证。
- 不增加秒级云轮询，不将定位塞入每 30 秒心跳的强制采集路径。

## 数据与共享边界

拟定快照包含 `schemaVersion / deviceId / observedAt / receivedAt / sequence / place / confidence / network / availability`；`location` 仅在用户另行启用精确共享时包含经纬度、精度和定位时间。服务器校验账号、设备归属、模式和大小，生成 receivedAt；按设备序号拒绝旧请求覆盖新状态，序号本地持久化，重新注册时换 epoch。

- 默认只同步环境标签，不上传家的中心坐标、原始 SSID/BSSID或轨迹。家与 Wi-Fi 规则先保存在本机。
- `observedAt` 与服务器收到时间分离；电脑按新鲜度标过期，例如超过配置采样间隔的两倍，且最少 10 分钟即过期。状态过期后不继续用于自动判断。
- 云端只保存每设备最新短期状态，初始 TTL 24 小时，提供立即删除；过期清理由存储过期/服务端任务完成，不能依赖手机再次上线。
- 不直接把精确坐标写进现有带不可变历史的通用 Object Sync。该存储会留下旧版本，与“默认不记录轨迹、可删除”要求冲突。实施时需通用设备环境快照接口或明确支持 TTL/无历史的存储路径。
- 同账号设备以外的 AI/外部授权默认看不到此数据；现有外部接入 scopes 不自动扩展。停止共享/撤销设备后取消待发、使云端记录失效，并让电脑缓存过期或接收清除事件。

## 第一版范围与验收

第一版完成：手动检测、家的区域、Wi-Fi 类型、省电后台上报、电脑读取最新状态、暂停/关闭、状态新鲜度与失败说明。及时模式、地理围栏、智能自动切换设备规则作为后续增量。

必须验证：近似/精确/仅前台/拒绝/撤销权限；系统定位关闭；室内漂移与家的边界；Wi-Fi 同名/VPN/无互联网/网络切换；断网恢复与旧请求晚到；账号切换；进程死亡/重启/强制停止；长时间静止与移动；后台耗电和实际执行间隔分布；停止后没有继续采集/上传；多台手机写入隔离；TTL与云端删除不留坐标历史。

先模拟器验证规则与失败路径，再用一加 Dev 实测后台调度和权限。默认保持亮屏；息屏调度效果需单独明确安排的最终验收，不能用亮屏实验宣称息屏后台可靠。实体生产包和用户原数据保持。实现后记录 24 小时实际采样时间和延迟，不能仅凭 Worker 返回成功宣布后台机制通过。
