## 信息量与关键覆盖

- 主日志加诊断日志约 27.7 MB，主日志和云诊断日志均按约 8 MB 单文件并保留一份轮转文件。云诊断信息过去又写入主日志，造成明显重复。
- “复用现有会话”在所选窗口出现约 11,710 次；“图标读取成功”约 6,322 次。两者都不是用户可操作事件，已移出默认主日志。
- 主日志现保留云诊断中的失败、阻止、冲突和重试冷却事件；逐对象成功读取等常规细节保留在专项诊断日志。
- 云诊断日志已改为队列批量写入，避免每条记录同步触发磁盘写入；写盘失败时保留未写记录待下次刷新。
- 每轮个人存储后台同步原有触发原因、上传/下载项目数、燕幕结果，但缺少可关联的编号和耗时。已加入 `runId` 和 `durationMs`，并把原先易被误认为上传量的 `yanmBytes` 改名为 `yanmSnapshotBytes`。
- 日志队列满时过去会静默丢行；现会在恢复写入时记录丢失行数。所选窗口未发现旧版曾记录的队列溢出信息，但旧版本来不会报告这一点。
- 诊断日志仍可能包含账号名、设备 ID、仓库路径和错误信息；不直接记录密码或 Token 值。图标下载失败的主日志现仅记录主机名和缓存键，不记录带查询参数的完整网址。分享原始日志前仍应检查个人信息。
