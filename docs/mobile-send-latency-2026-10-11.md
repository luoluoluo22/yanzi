# 手机发送延迟优化（2026-10-11）

## 定位

K70 的文字样本在电脑 18:53:15.522 进入局域网消息处理，18:53:15.526 完成剪贴板更新。本条不是定时轮询送达；原日志缺少点击和排队起点，无法据此计算端到端延迟。

原手机链路共用 Activity 后台队列；文字发送前同步注册云端设备；局域网聊天成功后仍同步等待云端提交。电脑现有 WebSocket 实时接收和离线补偿保留。

## 修改

- 文字、照片和文件聊天使用独立且有序的发送队列，发送前校验账号快照；增加排队和传输耗时日志，不记录消息正文或凭证。
- 两个文字发送入口移除每条消息的设备注册前置请求。注册仍由登录、前台连接管理和心跳维护；保留 401 刷新，不自动恢复被移除设备。
- 聊天收到有效局域网成功回执后立即返回。本地持久发件箱记录保留，通过后台服务立即请求云端补交；已有后台维护继续负责失败重试。
- 云端和局域网继续使用同一个 clientMessageId/clientOperationId，复用电脑既有去重。
- 远程执行命令的局域网结果仍是终态，不在云端重复执行。其他协议消息保留原来的提交路径。
- 后台补交合并并发请求；逐条发送前和附件准备后验证原账号快照，账号切换时保留原账号队列并停止该批发送。

## 验证

Dev、Dev AndroidTest、Release 构建及 lintVitalRelease。专用 YanziApi30 模拟器的 send-latency 原生 HTTP 测试覆盖：局域网立即返回且不前台提交云端、持久记录保留、相同 ID 云端补交、局域网拒绝后的云端回退、双路失败保留和恢复、账号变更阻止补交、命令失败终态不重放。另运行原消息接收、任务恢复与局域网故障测试。

测试使用本地 HTTP 夹具和虚拟账号，不涉及正式消息或服务端迁移。测试结果以本次执行记录为准；不得以模拟器结果代替 K70 性能验收。

## 交付边界

本轮代码开发与集成，不公开发布 APK、不安装 K70、不重启正式电脑宿主、不部署 Worker。手机实际提速等待安装候选版后复测。
