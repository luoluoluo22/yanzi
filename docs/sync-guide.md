# 5. 配置云同步

配置私有云盘同步，让扩展、面板布局与个人偏好设置在多台电脑间自动保持一致。

## 云同步概述

燕子当前包含两层同步：

- 燕子账号云端：同步账号级设置和兼容配置，由项目配置的 Cloudflare Worker、D1 与 R2 提供服务。
- 个人同步仓库：保存个人扩展包、扩展数据、配置备份和燕幕状态，空间由用户自己掌握。

个人同步后端目前支持 WebDAV、GitHub、Gitee、GitLab、Gitea 和 S3 兼容存储。账号云端和个人同步仓库用途不同，因此不能将所有同步数据都理解为“完全不经过第三方中转”。

## 方案 A：使用 WebDAV（推荐坚果云）

坚果云是国内对 WebDAV 支持较好的网盘，免费额度足够满足日常的同步数据量。

1. 注册并登录 [坚果云网页版](https://www.jianguoyun.com)，点击右上角昵称进入“账户信息”。
2. 点击“安全选项”，在下方的“第三方应用管理”中点击“添加应用”。
3. 输入应用名称（如 `yanzi`），点击生成，系统会提供一串专用的**授权密码**。
4. 打开燕子客户端的主设置页面，进入“云同步”选项。
5. 选择“WebDAV”，并填入以下信息：
   - **服务器地址**：`https://dav.jianguoyun.com/dav/`
   - **用户名**：您的坚果云登录邮箱
   - **密码**：刚刚生成的坚果云**授权密码**（注意：不是坚果云登录密码！）
6. 点击“保存配置”即可。燕子将自动在云端创建文件夹并完成首次同步。

## 方案 B：使用 GitHub 私有仓库同步

若您习惯使用 Git，可将数据托管在 GitHub 私有仓库。

1. 登录 GitHub，创建一个新的仓库（例如命名为 `yanzi-sync`），务必勾选将其设为 **Private（私有）**。
2. 进入 GitHub 的 Settings → Developer settings → Personal access tokens，生成一个新的 Token（需勾选 `repo` 范围所有权限）。
3. 打开燕子设置页面的“云同步”选项。
4. 选择“GitHub”同步方式，并填入以下信息：
   - **用户名**：您的 GitHub 用户名
   - **仓库名**：`yanzi-sync`
   - **分支**：`main`
   - **Token**：刚才生成的 Personal Access Token
5. 保存设置，数据将自动进行版本控制备份与同步。

## 其他个人同步后端

设置页还可以选择 Gitee、GitLab、Gitea 或 S3 兼容存储。各后端需要填写仓库/存储桶、分支或区域、路径前缀以及对应访问令牌；建议使用私有仓库或私有存储桶，并为燕子创建权限最小化的专用凭据。

## 当前同步边界

- 账号配置按对象同步。设置页会显示模式、健康状态、revision、来源设备、待上传队列和冲突；点击对象右侧“历史”可查看并恢复旧版本。恢复会产生新版本，不会删除现有历史。
- 同一对象被两台设备同时修改时，燕子保留本地冲突副本，并让用户选择“采用本地”或“接受远端”，不会静默按设备时钟覆盖。
- 燕幕不再由主配置快照重复写入：布局、状态索引和每个组件状态 key 都是独立 revision 对象，可在账号同步对象列表中查看来源、冲突和历史。旧 `yanm-state` 只保存对象权威结果的个人仓库备份镜像。
- 环境变量只同步名称和说明，变量值保留在各设备的 Windows DPAPI 加密存储中，需要在新设备上重新填写。
- AI 服务商名称、接口地址和模型会同步；AI API Key 保存在本机 Windows DPAPI 中，不写入账号对象或个人仓库，新设备需要重新填写。
- 窗口位置、设备 UUID、本地 Agent Token、备份目录和临时阅读状态不会跨设备同步。
- 登录燕子账号时，账号云端是主配置和扩展包权威；个人仓库中的主配置、扩展包和燕幕只做上传备份，不会反向覆盖账号状态。扩展私有数据仍保存在用户选择的个人仓库。未登录账号时，个人仓库继续按双向模式同步扩展包。
- 删除或彻底删除扩展会同时移除账号私有库关联并写个人仓库 tombstone；回收站和 tombstone 中的扩展不会被账号刷新重新安装，恢复后才重新加入账号私有库。
- 扩展包索引记录逻辑 revision、来源设备和删除状态。同一扩展在两台设备并发修改时，设置页会保留本地包/删除意图并提供“采用本地 / 接受远端”，不会只按设备时间决定。
- 扩展私有数据按 storage key 独立同步。每次写入先保存不可变版本，再更新带 revision、来源设备和 SHA-256 的当前对象；旧 `appdata` 文件仅用于兼容旧客户端。离线写入显示为 pending，并在周期或手动同步时重试。
- 扩展私有数据的本地 pending 与更高远端 revision 相遇时，两边内容都会保留，设置页“扩展私有数据并发冲突”可逐 key 选择版本；删除通过 tombstone 同步，不会被旧值复活。
- 每次个人仓库主配置发生实际变化时都会创建跨后端不可变恢复点，最多保留 30 个。设置页“同步记录 → 配置恢复点”可查看时间、来源设备、对象数量和大小；恢复前会校验 SHA-256，恢复结果作为新版本继续同步。
- Git/Gitee/GitLab/Gitea Token、WebDAV 密码和 S3 Secret Access Key 只保存在当前设备的 Windows DPAPI 中；账号云仅同步仓库、分支和路径元数据，Worker 不持有仓库访问凭据。新设备需要重新填写，建议始终使用权限最小化的专用密钥。

如果旧版本曾把 AI Key 写入 Git 类个人同步仓库，升级只能阻止新提交继续携带密钥，无法改写远端已有 Git 历史。建议撤销并重新生成旧 Key；如需彻底清理，再由仓库管理员按平台说明清洗历史。
