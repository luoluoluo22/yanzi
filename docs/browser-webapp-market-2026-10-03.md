## 本轮目标

1. 在现有“燕子浏览器助手”中加入网页小程序市场。
2. 用“小红书增强”作为第一个网页小程序验证运行时、右键交互、瀑布流过滤和燕子账号云同步。

## 当前实现

### 网页小程序市场

目录：`browser-extension/webapps/`

- `catalog.json`：内置网页小程序目录。

- `webapp_storage_get`
- `webapp_storage_put`
- `webapp_storage_delete`
- `webapp_storage_response`

桌面端复用 `AccountExtensionDataStore`，以：

`browser.webapp.<appId>`

作为云端数据命名空间。

浏览器端采用 local-first：

1. 本地修改立即生效。

3. 新连接时比较 `updatedAt`，较新的数据覆盖较旧数据。
4. Popup 可手动“立即同步”。

## 浏览器助手自重载（0.3.1）

新增开发期闭环能力：

- `POST /v1/browser/reload`：桌面端向当前浏览器助手发送自重载命令。
- 扩展收到 `browser_extension_reload` 后，先返回 `browser_extension_reload_ack`，其中包含当前版本号，然后调用 `chrome.runtime.reload()`。
- 重载后的扩展会自动重新连接燕子并再次发送 `register`。
- 因此以后可以用“请求已发送 → ACK → WebSocket 重连 → Registered successfully”完整判断重载成功。
- 这次仍需人工在 Edge 扩展页点击一次“重新加载”，使 0.3.1 首次进入正在运行的浏览器。以后不再依赖 GUI。
- 开发自重载会写入一次性刷新标记；新版 Service Worker 启动后会自动刷新当前正在运行网页小程序的标签页，避免旧 content script 留在已打开页面。

## 2026-10-04 瀑布流跨列干扰修复

发现旧版补位算法存在一个结构性问题：只要任意一列出现被屏蔽卡片，算法会把所有列重新按“卡片高度 + 推测间距”打包。小红书真实瀑布流各列的纵向间距并非必须等于统一估算值，累计误差可能让未发生屏蔽的列也获得错误 translate；表现为无论点击哪一列，最左列偶发整列消失，滚动触发下一轮布局后又恢复。

0.3.9 改为列隔离补位：

- 只处理实际包含隐藏卡片的列。
- 完全不修改其他列的 translate。
- 不重新推算整列布局，而是按小红书原生 Y 坐标，只减去被隐藏卡片原本占据的槽位跨度。
- 屏蔽前记录 nativeX/nativeY/nativeHeight，避免 display:none 后丢失几何信息。
- 点击屏蔽后不再额外执行“单卡片 reflow”，只走一次完整过滤帧，避免与小红书原生 masonry 更新竞争。
- 继续保持“不修改父容器 height”，无限滚动触发链不受影响。

真实登录页增加无损回归测试：临时隐藏目标列一张卡片，记录所有卡片 translate，运行补位后立即恢复现场，不写规则、不改屏蔽名单。

四列逐列测试结果：

- 第 1 列 targetX=0 → changedColumns=[0]
- 第 2 列 targetX=267 → changedColumns=[267]
- 第 3 列 targetX=534 → changedColumns=[534]
- 第 4 列 targetX=801 → changedColumns=[801]

四次 `untouchedColumnsStayedUntouched=true`，证明任意一列屏蔽时都不会再改动其他列。

### 0.2.0 观察模式与误判修复

早期 0.1.x 对直播进行了推断式补标签，导致普通视频也可能因为页面其他区域出现直播入口而被连续跳过。0.2.0 改为：

- 不再把 `live=true` 自动转换为“直播”关键词。
- “直播”只有在真实标题、真实标签或作者文本里出现时才算关键词命中。

- 命中后通过 Chromium CSS Highlight API 对原始页面文字 Range 做红色高亮，不修改 React DOM。
- 控制面板同时显示“命中关键词 · 标题/标签/作者”。
- 用户明确点击“启用”后才开启自动跳过；匹配后先高亮约 1.8 秒，再执行 ArrowDown。
- 点击“关闭”会立即取消待跳过定时器和正在进行的重试。
- 设置通过 `settings` 同步，启用/关闭状态可跨设备保存。

- 实际点击后可切换为“关闭”，再次点击可恢复观察模式。

## 2026-10-04 抖音商品误判收紧与观察窗拖拽

### 笔记行为统计

新增同步键 `noteStats`，仅在用户实际打开笔记后开始记录，按 noteId 聚合而不是为每次打开无限新增重复记录。

- 正文摘要与有限长度详情文本
- 话题标签

写入策略采用“本地高频、云端低频”：

- 本地 450ms 防抖聚合写入。
- 常规约 20 秒批量同步 `noteStats`。
- 关闭笔记后约 3 秒优先同步一次。
- 浏览器/桌面临时断开时保留 dirty 数据，重连后由现有网页小程序同步层对账。

实页验证曾打开笔记“谷歌DeepMind负责人：Gemini 4已进入后训”，成功读取 noteId、authorId、正文、标签、媒体类型以及点赞 14 / 收藏 3 / 评论 8，并在退出详情后得到 `openCount=1`、`lastDwellMs=141979` 和对应 close 事件。该开发测试记录随后已精确删除，不保留在用户建模数据中。

### 库存状态机

本地笔记不再无限循环 12 条固定内容，而是使用本地库存：

- `ready`：尚未安排到瀑布流。
- `assigned`：已经在视口下方安全区域预埋，但用户还没看到。
- `seen`：已经进入过视口，视为消费完成。

“剩余库存”定义为：

`ready + assigned但未seen`

只有该值 `<= 2` 时才允许调用 ChatGPT 补货；一次补 10 条。这样即使小红书提前加载很多 DOM，也不会因为卡片被提前分配到宿主而误判库存已经耗尽。

本地状态保存在 Chromium 扩展本地存储键：

`yanzi.xhs.local-feed.v2`

该测试库存不进入 `customCards` 云同步，也不写入 `noteStats`。

### 2026-10-06：网页小程序改为动态 content script 自动注入

- 浏览器助手版本：0.5.49
- 小红书增强网页小程序版本：0.7.22
- 修复后台/休眠小红书标签页在扩展开发重载后偶发 `inject_timeout / probe_timeout`，导致网页小程序没有真正运行的问题。
- 已安装网页小程序现在通过 `chrome.scripting.registerContentScripts` 注册为持久动态 content script；页面匹配时由 Chromium 自己负责注入，手工 `executeScript` 仅作为已打开旧页面的兜底。
- 动态脚本注册会跟随网页小程序的安装/卸载状态自动同步；开发重载时先完成注册，再刷新匹配标签页，因此刷新后的新页面天然加载最新版脚本。
- Service Worker 初始化不再等待后台标签页完成注入验证，避免一个休眠页面拖死整个扩展启动；运行时探针增加 `registeredContentScript` 字段，可区分“脚本未注册”和“业务生成失败”。
