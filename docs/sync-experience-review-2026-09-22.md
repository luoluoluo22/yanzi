# 同步与备份体验修复

## 观察与原因

只读检查本机同步状态，发现燕环页面与呼出方式、鼠标与手势触发两项存在保留的本机内容与云端内容差异。无法从现有记录证明每次修改的完整时间线，因此不能承诺自动合并；当前记录也没有用于三方合并的原始共同版本。没有改动或代替用户选择这些冲突。

同时发现 JSON 字段顺序会影响内容比较，已有冲突记录引用的云端版本落后于最新缓存。这些因素会制造不必要的冲突或使处理反复失败。

## 修改

- 顶部冲突提示可点击跳至同页的处理区域，列出不同的设置及云端来源，提供保留本机修改、使用云端内容。
- 比较 JSON 实际内容，忽略对象字段顺序，保留数组顺序与删除状态的差异。
- 同步后使用已保留的本机副本核对云端，相同则取消冲突；不同则保留本机副本并更新云端版本。不会拿已经应用云端内容的界面快照来误消除冲突。
- 上传版本竞争遇到内容已一致时，按同步成功处理。
- 用户查看后如果后台更新了冲突版本，要求重新查看；服务器版本检查继续保护后续上传。
- 历史备份以日期和来源为主，隐藏突出显示的哈希与长编号，原始差异保留为技术详情。设备标识匹配时显示本机，其他设备保留名称。
