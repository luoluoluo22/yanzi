# 任务中心与数据恢复首版（2026-10-04）

## 入口与范围

- 手机：我的 → 任务中心＋数据恢复；候选 Dev 版本 0.2.52-dev。
- 电脑：设置 → 燕窝 → 任务中心＋数据恢复。
- 当前任务列表属于本机当前账号与服务器；不会跨账号合并，也不会凭设备名称去重。
- 新版本保留消息、文件传输和远程电脑请求的操作标识、目标、状态与最多 8000 字结果摘要。历史上已经清掉的回执不反向补录。
- 文件处理任务读取现有 companion-transfers 记录，覆盖上传、处理、回传及完成状态；同一操作与消息回执合并为一条。
- 查询原任务只读取既有消息/任务。文件处理查询仅在原任务已经提交后查询或继续接收已有结果，不创建新任务。
- 尚未纳入应用商店下载、所有第三方扩展内部任务与 ChatGPT 桥接层完整生成生命周期；短命令完成不等于其内部异步 AI 作业完成。

## 持久化与不重复执行

- 手机 task-journal 按服务器＋JWT sub 的 SHA-256 分区，文件临时写入、fsync、原子替换；电脑同样按服务器＋账户分区保存。
- 日志不存令牌和请求正文；保留结果摘要用于用户查看，执行队列继续使用现有 outbox/执行回执机制。
- 同一操作标识只产生一条记录，成功/失败等终态不会被迟到的 pending 回执回退；目标保持原设备。
- 网络超时为“结果待确认”；查询失败不代表操作失败。未取得云端消息标识时不提供会重新执行的按钮，现有持久队列负责原消息投递。
- 重启后中断的 executing 记录显示结果待确认，避免长期伪装成正在执行。
- 最多保留约 1000 条完成记录；未完成记录不因限额直接丢弃。

## 恢复边界

- 使用已有 /v1/sync/objects、changes、history、objects/{id}/restore 接口；列表包含 tombstone，并支持分页。笔记账号共享文档也是 extensionData.v1 对象。
- 先读取当前对象版本，展示历史内容，二次确认后携带 expectedRevision、restoreRevision 恢复。恢复生成新版本并保留历史。
- 这是整个同步对象的恢复点，可能包含多条笔记/设置；不是逐条笔记回收站。预览最多展示 8000 字摘要。
- 手机可恢复独立对象。yanm.componentState / quickPanel 分组 / radialMenu 页等关联索引对象只预览，明确引导到电脑恢复，避免对象恢复后仍从布局索引中缺失。
- 电脑沿用现有 RestoreCloudObjectVersionAsync 修复相关索引；索引恢复属于现有多步操作，索引连续冲突可能出现“对象已恢复、索引待修复”的部分完成，不宣称整组事务原子性。
- 恢复 POST 不做网络错误自动重试；409 明确要求重新预览，不自动提升 expectedRevision 强行覆盖。
- 账号/令牌变化时阻止旧页面应用结果，需重新打开页面。页面进入后台核验已删除设备；恢复写入前再次核验注册状态，删除设备会清除本机登录，不自动重新注册。网络离线时仍保留本地任务查看。
- 文件引用不等于文件备份：未备份且永久删除的 MediaStore 照片或电脑文件无法凭此接口找回。
