# 求职（V0.4）

## 产品目标

面向国内传统企业的 AI 转型岗位建立每日求职闭环，不追求最高薪资或海量投递。

核心循环：

发现职位 → 判断是否是真实传统企业 AI 转型 → 结合个人简历判断匹配 → 反向评估企业/Boss/工作强度 → 形成候选 → 人工确认投递 → 记录查看/联系/面试/Offer反馈 → 调整后续策略。

## 当前平台

- 智联招聘
- 使用智联公开 SSR 搜索页抓取全国职位列表。
- 当前默认 12 个关键词 × 3 页 × 每页 20 条，单轮最多读取 720 条原始结果并按职位 URL 去重。
- 抓取会话禁用 Cookie，避免智联连续请求切换页面结构导致后续页解析为空。
- 对高优先级新职位继续读取公开职位详情和公司介绍。
- 前期全国调查，不按城市过滤。
- 暂不自动登录、自动海投或自动代聊。

## 我的简历

简历是长期基础资料，保存在小程序本地数据目录的 `resume.json`，可以随时修改。

当前功能：

- “我的简历”编辑器
- 在线预览
- 导入 DOCX / TXT / MD / JSON 已有简历
- 导入无法完全结构化时保留原文，不丢内容
- 导出 DOCX 附件简历或 TXT 简历
- 简历修改后自动重新计算岗位匹配
- 读取智联在线简历：复用 Edge 当前登录态，不保存账号密码，不复制 Cookie
- 对比本地主简历与智联在线简历，按“关键差异 / 提示差异”分类
- 同步智联：个人优势、已有工作经历、缺失工作经历、求职意向可自动写入
- 新增工作经历时调用智联自己的职位分类推荐，避免错误沿用旧职位编码
- “管理智联”可查看线上工作 / 项目 / 技能 / 教育节点；删除需要二次确认
- 每次读取/修改线上简历都保存 JSON 快照和历史版本
- 投递和打招呼前强制校验简历同步状态；存在关键差异时直接阻止提交
- AI 可通过 `--resume` 唤起简历编辑器
- AI 可通过 `--resume-read` 读取智联简历
- AI 可通过 `--resume-diff` 对比本地与智联
- AI 可通过 `--resume-sync` 执行安全同步
- AI 可通过 `--export-resume=<path>` 导出当前附件简历

电话号码、邮箱等个人字段不参与公开岗位扫描，只在本地简历资料和后续确认投递阶段使用。对教育年月、技能熟练度、旧经历删除等无法从本地主简历确定的信息，不自动猜测。

## 搜索与评分策略

- 搜索关键词覆盖：AI应用、AI赋能、大模型应用、AI自动化、智能体、数字化转型、AI应用专员、AI工具、AI产品经理、AI工作流、AI数字化、AI剪辑。
- 当前城市：成都；全国岗位仍全部进入样本池。
- 地点只作为轻量现实成本因子，成都加分，异地不淘汰。
- 薪资不是越高越好。
- 当前舒适区：4500–6500 元/月，目标约 5000 元/月。
- 当前高薪警戒：10000 元/月，明显高于此区间的岗位会因竞争和工作强度风险降权。
- 评分维度：传统企业转型、简历匹配、经验匹配、岗位匹配、薪资舒适度、地点成本、Boss/工作强度风险、竞争风险。
- 经验要求使用硬上限：校招/应届最高约 38–42 分；1 年以下最高 46 分；1–3 年最高 55 分；3–5 年且与当前 10 年经历差距明显时最高 64 分。
- 负责人、总经理/董事长直接汇报、全公司推动、从0到1、职责过宽、高薪等会降权。

- 宿主闲置 15 分钟后可触发。
- 持续闲置每小时再次检查。
- 同一天自动扫描只执行一次，避免重复抓取。
- 手动“扫描智联”可以强制刷新。

## 2026-10-11：长期投递档案与 HR 会话安全工作流（已完成开发，尚未激活正式安装）

- **独立于滚动职位缓存的长期档案**：`application-ledger/events.jsonl` 是只追加并落盘的状态事件；`application-ledger/snapshots/<岗位ID>.json` 保存单岗位最新状态。已投递状态即使被新扫描淘汰，也可以恢复。
- **跨进程防覆盖**：对 `JobRepository.LoadJobs/SaveJobs` 使用命名互斥锁，合并已有记录与档案后原子替换 `jobs.json`。通过合成数据的并发写入、旧状态回退、事件去重与损坏快照恢复测试。
- **迁移入口**：`--ledger-bootstrap` 将现有已投递岗位归档，不修改简历或触发招聘平台操作。首次正式启用前应备份原有 `ExtensionStorage` 数据。
- **精确 HR 会话绑定**：`--hr-bind=<岗位ID>|<智联会话链接>|<最后一条本人已发送的原文>`；只读核对真实公司、岗位及聊天正文后才绑定。已有真实回复档案中的会话可直接识别。
- **监测与待核实**：`--hr-review=<岗位ID>` 或 `--hr-review-all` 检查已绑定会话；`--hr-queue=<岗位ID>` 查询待核实问题。消息发送方方向不确定时只记录，不贸然自动回复。
- **回复防重**：`--hr-verify=<岗位ID>|<消息指纹>|<已核实的入站原文>` 由核实操作确认身份，随后 `--hr-send=<岗位ID>` 先检验公司、岗位、原问题、是否已回复，再记发送意图、执行发送、核查「送达」，不能因网络超时自动重复发送。
- **事实型草稿**：仅对可以从 `resume.json` 核实的专业问题生成结构化答复；未知/敏感问题留给人工。旧版按未读列表直接发固定模板的实现已停用，设置中的相关功能强制为关。
- **隔离回归**：`cd prototypes/job-agent/tests`，执行 `dotnet restore Smoke.csproj --configfile NuGet.Config` 与 `dotnet run --project Smoke.csproj --no-restore`。已在实际智联登录态下只读核查云境清禾会话，正确识别最近回复来自本人，无新问题，未发送任何测试消息。

**当前边界**：小程序仍无法通过现有浏览器能力可靠获取所有消息的发送方标识，也未自动发现和绑定所有新招聘会话；因此“零人工全自动代聊”和自动学习改分尚未完成。新代码先经源码编译与非破坏测试，正式安装仍须按部署门禁执行。新版功能没有写入当前已安装的 `v0.4.0` 小程序，不得将测试通过视为正式上线。
